# BBONG (뽕) — AI 활용 기술 문서

## 1. 사용 AI 도구

| 도구 | 용도 |
|---|---|
| Claude Code | 기획 정리, 룰 명세, 코어 엔진, 서버, 클라이언트, 배포까지 전 과정의 페어 프로그래밍 |
| Claude 서브에이전트 | 배포본 UI 디자인 리뷰나 코드 탐색처럼 떼어낼 수 있는 작업을 별도 컨텍스트로 위임 |

## 2. 프로젝트 구조와 AI의 역할

```
core/BbongCore     순수 C# 룰 엔진. 게임 규칙 전부 (NUnit 테스트 136개)
server/BbongServer ASP.NET Core. 계정/지갑 API + WebSocket 실시간 멀티 (테스트 163개)
client/BbongClient Unity 6. 코드로 생성하는 UI, 공용 게임 테이블 뷰(GameTableView)
tools/             봇 시뮬레이터(BotSim), 부하 시뮬레이터(BbongLoadSim)
scripts/           Playwright 자동 플레이 테스트, 100인 동시 접속 부하 테스트
```

규칙부터 문서로 정리고 시작했습니다. 구두로 설명한 전통 놀이 규칙을 AI와 문답으로 주고받으며
`docs/rules.md`로 정리한 다음, 그 문서 하나만 기준 삼아 코어를 구현했습니다. 또이또이 구성이나
바가지 점수, 공동 1등 절사처럼 애매한 대목은 AI가 엣지 케이스를 먼저 제안하고 사람이 결정하는
방식으로 좁혔습니다.

코어와 서버는 전부 TDD로 진행했습니다. 실패하는 테스트를 먼저 쓰고, 통과시키고, 정리하는 사이클을
반복해서 지금 자동화 테스트가 299개입니다.

서버 기반 멀티는 좌석별로 개인화한 스냅샷(RoundView)과 이벤트 프로토콜을 설계하는 데서
출발했습니다. 방마다 단일 소비 루프를 둬 선착순 뽕 경합을 막았고, 5초 턴 타이머와 이탈 시 봇
대체 같은 온라인 전용 규칙도 AI와 같이 작성했습니다. 화면 쪽은 연습과 멀티가 공용 `GameTableView`
하나만 쓰도록 리팩터링했습니다. 모드마다 UI와 문구가 분리되는 문제를 구조에서 제거하였습니다.

### AI 디자인 리뷰

사람이 스크린샷을 찍어 지적하는 대신 리뷰 자체를 에이전트에 맡겼습니다. 디자인 리뷰 전용
서브에이전트가 Playwright로 배포된 웹 빌드를 직접 돌아다니며 화면을 모읍니다. 로그인부터
인게임 테이블까지 9개 화면을 10컷으로 훑는 `scripts/ui-crawl.py`가 그 도구입니다. 리뷰
에이전트가 문제 목록을 돌려주면 구현 담당이 코드에 반영합니다. 이 루프를 두 번 돌렸습니다.

1차 결과가 커밋 `6b6b821`입니다. 모드별로 색을 달리한 글리프 카드, 모바일 최소 터치 높이 48dp
하한, 선택 칩 색 반전, 게스트 CTA 승격, 내 좌석 금색 링과 버림 더미 딤 처리가 들어갔습니다.
2차는 `b9eeba4`인데 훨씬 잘게 들어갔습니다. 버튼의 hover, pressed, disabled 상태를 명시하고
비활성 사유를 문구로 띄웠으며, 리더보드는 열별 정렬을 맞추고 본문 크기를 키웠습니다.
좌석 패널 9-slice 통일, 빈 자리 자리표시 문구, 라벨과 칩의 간격 리듬, 그림자 단계 정규화도
같은 배치에서 처리했습니다.

### 그 밖의 작업

- 디버깅: Unity Editor.log를 AI가 직접 읽고 WebGL 손패 뭉개짐 같은 레이아웃 버그의 원인을
  코드 수준에서 짚어냈습니다.
- 판돈 멀티: 유저별 지갑 락(PostgreSQL advisory lock)으로 동시 인출 경합을 막고, 입장
  에스크로부터 이탈 몰수, 우승자 정산까지 TDD로 구현했습니다. 빠른매칭은 10초를 기다린 뒤
  사람처럼 보이는 봇이 랜덤 간격으로 자리를 채우고, 정원이 차면 5초 카운트다운 후 시작합니다.
- 자동 플레이 테스트: Playwright가 실제 웹 빌드를 좌표 클릭으로 조작해 로그인부터 게임 진행까지
  4종 시나리오를 확인합니다. 여기에 WebSocket 클라이언트 100명이 랜덤 조건으로 매칭돼 실게임을
  완주하는 동시 접속 부하 테스트를 붙여 지갑 정합과 완주율을 봤습니다. 배포 서버에서 100명 전원
  완주 3회, 이상 0건이었고, 규칙을 크게 바꾼 뒤에는 40명 재검증으로 이상 없음을 확인했습니다.
  봇 턴에 손패를 마구 눌러대는 퍼징으로 실제 레이스 버그를 재현해 고친 적도 있습니다.
- 게임 히스토리: 온라인 게임의 딜 시점 손패 스냅샷과 드로우, 버림, 뽕, 족보, 스톱, 정산 이벤트를
  PostgreSQL에 남깁니다. 관계형 3테이블에 JSONB 페이로드를 얹은 구조이고, 참여자 본인이
  `/me/games`와 `/games/{id}/events`로 조회합니다. CS와 디버깅을 염두에 둔 장치입니다.
- 배포 자동화: WebGL용 브라우저 WebSocket 브리지(jslib), GitHub Pages Actions 배포, fly.io
  컨테이너화, Unity CLI 빌드 파이프라인을 AI가 작성했습니다. 코드 수정부터 빌드, 배포, 배포본
  검증까지 사람 손 없이 돌아갑니다.

## 3. 게임 내 AI (봇)

`core/BbongCore/Ai/Bot.cs`에 Easy, Normal, Hard 세 난이도의 휴리스틱 봇이 있습니다.

버릴 카드는 숫자가 높은 것부터 보되 페어는 지키고, 쌍이나 연속을 만들 여지가 있는지 쓸모도를
따져 고릅니다. 스톱은 손합 구간별 확률 밴드로 정합니다. 조건만 맞으면 무조건 부르던 편중을
없애려고 넣은 장치입니다. 여기에 카드 카운팅을 얹었습니다. 버림 더미와 이미 나간 패와 내 손,
그러니까 공개된 정보만으로 상대가 나를 언더컷할 확률을 조합으로 계산해서 바가지 위험이 높다
싶으면 스톱을 참습니다. Hard는 순위까지 봅니다. 누적 점수상 1등이면 빨리 손을 털어 리드를
굳히고, 뒤지고 있으면 스톱 대신 두 번 뽕을 노려 상대에게 빚을 떠넘깁니다.

튜닝은 감이 아니라 측정으로 했습니다. 라운드 종료 사유 분포를 재는 시뮬레이터(`tools/BotSim`)로
난이도별 3,000라운드를 돌려 전후를 비교했고, 순수 스톱으로 끝나는 비율을 58%에서 43%까지
내렸습니다.

온라인에서 이탈하거나 응답이 없는 자리는 이 봇이 이어받습니다. 맞춤게임의 매칭 대기 자리도
Hard 봇이 채워서 게임이 항상 성립합니다.

## 4. 주요 프롬프트/지시 예시

### 프로젝트 킥오프 프롬프트 (초기 세션 요지 재구성)

프로젝트를 시작한 첫 세션들의 지시를 요지로 복원한 것입니다.

> "한국 전통 카드 놀이 '나이롱뽕'을 온라인 게임으로 만들려고 해. 내가 아는 규칙을 설명할 테니
> 애매한 부분은 네가 엣지 케이스를 질문해서 함께 확정하고, 확정된 규칙을 `docs/rules.md`
> 명세로 먼저 작성하자. 그 명세를 단일 기준으로 삼아 구현해."
>
> "구조는 셋으로 나눠: ① 게임 규칙 전부를 담는 순수 C# 코어(클라·서버가 공유),
> ② Unity 클라이언트, ③ 서버 기반 온라인 멀티를 위한 ASP.NET Core 서버.
> 최종 목표는 플레이스토어/앱스토어 출시야."
>
> "개발은 TDD로: 실패하는 테스트를 먼저 쓰고(Red), 통과시키고(Green), 정리해(Refactor).
> 버그 수정도 재현 테스트부터. 그리고 규칙·문구·UI는 모든 모드에서 반드시 동일해야 해."

### 개발 중 대표 지시 (실제 세션 원문 요지)

- "Red → Green → Refactor 순서를 지켜 구현해줘. 버그 수정도 재현 테스트부터."
  전역 지침으로 걸어둔 문장입니다.
- "게임 판 UI를 통일하고 멘트도 통일해야 해. 하나의 틀로 연습/친구/일반 게임이 참여자만
  다르게 돌아가야 해." 공용 GameTableView를 뽑아낸 리팩터링이 여기서 나왔습니다.
- "5초 안에 카드를 내려놓지 않으면 자동으로 진행되는 규칙, 그리고 이탈한 유저는 봇이
  대체해서 한 게임이 끝날 때까지 진행되게 해줘."
- "족보 선언 문구가 어디서는 '스트레이트', 어디서는 'Straight'로 나오면 안 돼."
  이 지적으로 코어에 표시명 단일 출처(MeldNames)를 만들었습니다.
- "친구방을 웹으로 배포해서 GitHub Pages로 플레이할 수 있게 해줘." WebGL WebSocket 브리지와
  쿼리 토큰 인증, Pages와 fly.io 배포 구성이 이 한 줄에서 시작됐습니다.
- "맞춤게임은 시작하기 하나로. 조건 맞는 방이 없으면 방장이 돼서 대기하고, 10초 뒤부터
  봇을 실제 유저인 것처럼 입장시켜. 정원이 차면 5초 카운트다운 후 시작."
- "100명의 유저가 랜덤 조건으로 매칭해서 게임을 즐기는 시나리오를 테스트하고, 이상한 점이
  없어질 때까지 수정-배포-재시험을 반복해줘." 부하 테스트 하네스를 짜고 매칭 레이스 버그를
  잡은 뒤 배포본에서 100/100을 확인했습니다.
- "봇이 버려진 패를 카운팅해서 바가지를 쓰지 않게 하고, Hard는 순위를 고려해 1등이면 빨리
  털고 뒤지면 바가지를 유도하게 해줘."
- "손패 2장이 같으면 전원에게 알리고, 예고 없이 터지는 뽕+자연뽕 콤보는 벌점을 키워줘.
  규칙이 바뀌었으니 플레이어블 튜토리얼도 전반적으로 재구성해줘." 쌍 공개 UI와 자연뽕 바가지
  50점, 7개 레슨 튜토리얼이 이때 한꺼번에 갈렸습니다.
- "배포된 웹 화면을 직접 돌아다니면서 스크린샷을 찍고, 디자인 관점에서 문제를 지적해줘.
  구현은 하지 말고 지적만."

### 서브에이전트 위임 지시 (디자인 리뷰, 요지)

리뷰하는 쪽에는 구현 권한을 주지 않았습니다. 지적하는 에이전트와 고치는 에이전트를 나눠야
지적이 무뎌지지 않는다고 봤습니다.

> "당신은 게임 UI 디자이너입니다. `scripts/ui-crawl.py`로 배포본 화면을 순회해 스크린샷을 모으고,
> 각 화면에서 ① 시각적 위계 ② 터치 타깃 크기 ③ 상태 피드백(선택/비활성/눌림) ④ 정렬·간격 리듬을
> 기준으로 문제를 지적하세요. 코드는 고치지 말고, 화면별 지적 목록만 돌려주세요."

## 5. 외부 에셋 / 오픈소스 출처

| 항목 | 출처 | 라이선스 |
|---|---|---|
| UI 스프라이트(버튼·패널·코인) | Kenney (kenney.nl) | CC0 |
| 폰트 Pretendard | github.com/orioncactus/pretendard | SIL OFL 1.1 |
| 카드 색상 팔레트 | Okabe-Ito 색각 이상 안전 팔레트 | 공개 연구 자료, 자유 사용 |
| 카드 아트, 효과음 | 코드로 절차 생성 | 자체 제작 |
| 엔진/프레임워크 | Unity 6 (Personal), .NET 8, PostgreSQL, Npgsql/EF Core | 각 표준 라이선스 |
| 테스트/자동화 | NUnit, Playwright(Python). 빌드 산출물에는 포함되지 않는 개발 도구 | MIT / Apache-2.0 |
| 배포 | GitHub Pages, GitHub Actions, fly.io, Docker | 각 서비스 약관 |

게임 화면의 카드 아트와 좌석 패널, 효과음은 외부 에셋을 쓰지 않고 전부 코드로 만듭니다
(`TableArt.cs`, `UiKit.cs`). 저장소에 들어 있는 외부 이미지는 Kenney의 CC0 UI 스프라이트
네 장이 전부입니다.

타인의 게임 코드나 아트를 복제한 부분은 없습니다. 게임 규칙은 전통 민속 놀이 방식을 자체적으로
정리한 것이고, 정리한 결과는 `docs/rules.md`에 있습니다.
