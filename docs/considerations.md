# BBONG 고려사항 · 리스크 대장 (v0.1)

> 게임 로직(`rules.md`)·구성(`architecture.md`) 외의 잔여 리스크/숙제.
> 코드엔 당장 영향 없으나 멀티 설계·출시 전 반드시 처리. 심각도: 🔴높음 🟠중간 🟡낮음.

---

## 🔴 R1. 웹보드게임 규제 분류 (최대 변수)

- 전체이용가를 받아도, GRAC가 BBONG을 **"웹보드게임"으로 분류**하면 별도 규제 적용.
  - 월 결제 한도, 1회 베팅 한도, 일일 손실 한도, 자동 진행 제한 등.
- Rummikub은 **"두뇌게임"** 인정으로 회피. BBONG은 **"뽕"·화투 원작**이라 분류 심사 불리 가능.
- **대응**: 출시 전 게임물 등급/웹보드 분류 **법무 검토 필수**. 분류 결과에 따라 판돈 시스템 재설계 가능성.
- 영향 시점: Phase 6(출시) 전. 단 Phase 4~5 수익화/멀티 설계 시 한도 적용 가능성 염두.

## 🟠 R2. 담합(짜고치기) 어뷰징

- **친구 + 판돈 + winner-takes-all** = 한 계정에 포인트 몰아주기 통로.
- 환전 불가라 현금 피해 없으나, 랭킹/재화 부정 축적·신뢰 훼손.
- **대응**:
  - 판돈 방은 **실유저 전용**(봇 미참여, §이탈 시에만 AI 대체).
  - 동일 IP/기기/반복 친구 매칭 탐지, 이상 정산 패턴 모니터링.
  - 랭킹은 판돈 결과와 분리하거나 가중치 조정.

## 🟠 R3. 재화 경제 밸런스

- 환전 출구 없음 → faucet(광고·일일지급·IAP) vs sink(판돈·아이템) 균형 설계.
- **신규/파산 유저 구제** 필수: 잔액 0 시 게임 불가 → 이탈. 일일 무료 지급·파산 보너스.
- 포인트 인플레이션 방지(과도한 광고 보상 ↔ 판돈 회수율).

## 🟡 R4. 개인정보 · 결제 (법규)

- 소셜 로그인 수집 → 개인정보처리방침·동의(PIPA).
- 미성년자 결제 환불 정책, 본인인증(스토어 기본 + 필요 시 자체).
- 환불·분쟁 대응 원장(architecture §5 ledger 연계).

## 🟡 R5. 상표 · IP

- **"BBONG" 상표 출원** 검토. "나이롱뽕"·화투 직접 연상 명칭/문구 회피.
- 아트/아이콘 **오리지널 제작**. Rummikub 등 기존 게임 에셋 복제 금지(UI 레이아웃 아이디어 차용은 무방).

## 🟡 R6. 실시간 공정성 (멀티)

- 뽕 2초 인터럽트(`rules.md` §4-1)의 **레이턴시 보정** — 서버 수신 시각 기준 통일, 클라 표시 지연 보상.
- 재접속/일시 끊김 복구, 동시 입력 충돌 해소(서버 권위 직렬화). 턴제라 난이도는 낮음.

## ✅ 이미 반영됨

- 색약 접근성: 명도/패턴 병행 (`rules.md` §1, README).
- 환전 불가: `rules.md` §9, `architecture.md` §5.
- 서버 권위 치트 방지: `architecture.md` §1, §5.
